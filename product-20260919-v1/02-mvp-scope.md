# 工作 2：MVP 功能范围与验收

状态：范围建议 v1，待整体草图确认。上游 Uxx 对照见 [功能拆解](01-upstream-analysis.md)。

## 1. 已确认的产品边界

用户在本轮明确选择：

- 浏览器 Web 应用，电脑端优先，云端运行，无本地安装或 API Key 配置。
- 用户导入职位链接或全文；首版不做产品内职位搜索。
- 美国英语求职者优先；界面和生成材料采用英语。

首批人群建议：已有简历、正在主动申请美国白领岗位、希望逐份定制材料的非技术用户。运营、营销、客户成功、项目管理等均可作为招募方向；不是只服务程序员。首版暂不针对学术 CV、联邦专用简历或复杂移民法律判断。

一句话定位：

> Turn a job posting into a tailored application you can review and trust.

这是“申请准备与跟踪工作台”，不是“自动找工作机器人”。产品暂称 Job Application Workspace，不作正式品牌命名。

## 2. MVP 要验证的价值

用户已经在 LinkedIn、Indeed 或公司官网找到职位，不愿在聊天工具里反复解释经历、复制提示词、整理输出和保存版本。

核心闭环：

```text
导入简历 -> 确认事实 -> 导入职位 -> 看适配依据
-> 主动选择定制 -> 审核与修改 -> 导出 -> 自行投递 -> 手动跟踪
```

差异化假设不是“也能生成求职信”，而是“同一份可核实资料，贯穿适配判断、定制、审阅、版本留存与跟踪”。是否成立必须通过用户试用验证。

## 3. 优先级方法

P0：缺少就无法完成核心闭环，或会造成明显信任/数据风险。
P1：确认核心价值后扩展；P2：不纳入当前方向。

“高频”不是“所有人天天用”。资料初始化是低频但必需；事实复核和版本管理是系统每次执行的基础能力；面试准备高价值但阶段性使用。没有遥测数据，不做虚构 RICE 分数。

## 5. 明确不做

| 来源 | 延后功能 | 原因 / 回归条件 |

| U19、U20 | 自动跟进建议、感谢信、长期沉默清理 | 首版可备注与更新状态，无自动发送或自动判定无回复 |

| U22、U24 | Gmail、Notion 同步 | OAuth、权限、误判与客服复杂度高；内部列表先满足需求 |
| U03、U25 | 公开资料扩充、技能路线图 | 首版优先处理用户主动提交的事实，避免变成职业规划大平台 |
| U26 | 薪资数据库/谈薪建议 | 不具备授权数据；允许提取职位明示薪资，但不估算市场薪酬 |
| U27 | 模板市场、自定义模板代码 | 首版单模板，避免布局/任意代码执行问题 |

| 云端新增候选 | 聊天主界面、独立统计大屏、支付订阅系统 | 核心闭环不依赖；小规模邀请测试先使用额度，无付费墙。M12 是职位内受限追问，不等于聊天主界面 |

首版测试不做结账页面，并不意味着永久免费。收费方式、价格和付费实验单独确认后设计。

## 6. 核心行为规则

### 6.1 资料与职位

- 主资料是事实源；定制草稿不能自动反向污染主资料。
- 系统可提取信息，但首次确认前不能将解析结果当作用户已核实事实。
- 年龄、照片、婚姻、SSN、证件扫描件不收集；工作授权只询问自报状态和是否需要赞助，允许“不确定/暂不提供”，不索要证件。
- 建议初始上传限制：PDF/DOCX 不超过 10 MB、20 页；属于实现前待确认参数。扫描件暂不 OCR，提示粘贴文本或手填。
- 公司、职位名、完整正文是分析最小输入。薪资、截止日期、授权要求未写明时显示 Not stated，不猜测。
- URL 仅读取经允许的公开页面；LinkedIn 等限制来源直接提示粘贴正文。登录墙、验证码不绕过，不要求提供招聘平台账号。
- 导入时保存原文、输入方式、来源 URL（可空）、时间；正文修改产生新快照。
- 重复 URL/岗位编号提示打开现有记录；公司同名/职位同名只能提示疑似重复，允许创建独立申请。

### 6.2 适配判断

- 展示 `Supported`、`Gap`、`Needs confirmation` 三类要求和对应原文/资料证据。
- 首版无 0–100 综合分；以 `Worth considering`、`Review gaps`、`Not enough information` 等建议标签辅助决定，明确不是招聘结论。
- 工作授权、地点、语言分别显示声明与职位原文。资料未填写就是未知，不是失败。
- 明确冲突先提示，允许更正资料或知情继续；不因模型推断隐藏职位，也不自动宣告申请资格。
- 公司文化、签证政策、薪酬待遇等没有来源时不补写；不承诺 ATS 通过率。
- 适配结论优先用自然语言表达。数量化表述（如「6 / 9 条要求有证据」）只在系统确实完成结构化抽取时出现；抽取失败时不得显示 0 或任何伪造条目。

### 6.3 生成、审核与输出

- 点击 Tailor resume 才启动生成，评估完成不自动消费生成额度。
- 固定流程：起草 → 独立审阅阶段 → 修订 → 用户检查。独立审阅是服务端流程，不要求使用 Claude Code 子代理。
- AI 新增经历、指标、技能须关联已确认资料；无依据时删除或请求补充。模型审阅不能代替用户最终核对。
- 用户添加新事实时明确选择“仅本申请”或“同时更新 My profile”；两者都记录用户来源与确认时间。
- 首版仅结构化分段编辑，不做任意版式拖拽或复杂多人编辑。
- 更改内容后以前的检查失效；导出必须对应当前版本，不能下载旧 PDF 却显示新内容。
- 1 或 2 页 Resume 均可；第一页信息层级优先，不默认放照片、年龄和完整住址；US Letter。
- PDF 检查：生成成功、页数、文字可提取、姓名/邮箱等关键文字、明显溢出/空白异常；DOCX 检查文件完整性与内容一致，不声称 Word 中分页完全一致。
- 内容问题未解决不能给出“已核实”标记；解析/版面检查失败不能给出“已通过”标记。修复或提供对应有效格式的降级出口。
- AI 派生的界面文案必须能降级：结构化结果（要求条数、改动归因、逐条证据）拿不到时，改为定性表述并给出重试入口；不得编造计数、不得把「拿不到」显示成 0、不得虚构改动理由。

### 6.4 状态和版本

业务状态与后台任务状态分开：

```text
业务：Saved -> Drafting -> Ready -> Applied -> Interview -> Offer -> Closed
关闭原因：Rejected / Withdrawn / No response / Accepted / Offer declined
任务：Queued -> Running -> Succeeded / Failed / Cancelled
```

- Ready 指当前申请材料已审阅且校验通过，不等于已经投递。纯下载、打开职位网站都不能设置 Applied。
- Mark as applied 需要确认实际日期与提交版本；若材料在站外制作，允许选择“外部材料，未存档”，不强迫先生成。
- 可以直接记录面试或结果，不强迫按阶段逐步点；补充实际投递日期或标记未知，不伪造日期。
- 状态修改记录事件；更正通过追加更正事件完成，不默默抹掉历史。
- 已提交快照不变；后续改稿另存版本；同一公司同一岗位再次申请也创建独立申请 ID。
- 截止日期属于职位属性，不覆盖业务状态；过期职位可能已进入面试。
- `No response` 只能由用户选择，不由等待天数自动推导。

### 6.5 职位内追问（M12）

- 回答范围严格限定在「当前职位原文 + 用户已确认的资料」。超出范围的问题直接说明无法回答，不用通用职业建议填充。
- 每条回答必须能定位到来源：职位原文行，或用户已确认的资料条目。无法定位时不得作为结论输出。
- 原文与资料都没有的（例如公司文化、内部晋升），回答「原文未说明」，并说明这属于未核实范围。
- 追问不执行任何写操作：不能改状态、不能改资料、不能触发下载或投递，避免把问答变成隐式命令入口。
- 载体是 P05 内的一个提问框，不是常驻聊天窗口；不保存为独立对话历史，也不做多轮长期记忆。
- 提问内容不计入生成额度前先确认；若计入，需在额度说明里写明。

## 7. P0 验收标准

| 编号 | 必须可演示的结果 |
|---|---|
| A01 | 新用户不安装任何工具、不填写模型 Key，在浏览器建立私有空间；过期链接可重发 |
| A02 | 上传/粘贴后逐项修正解析结果；失败保留输入；必需信息不足时定位字段 |
| A03 | URL 成功可预览原文；受限站可改粘贴；不能只靠标题生成分析 |
| A04 | 每条适配结论有职位要求与资料依据；资料缺失显示未知而非不合格 |
| A05 | 用户不点击定制时只保留职位；求职信可不生成 |
| A06 | 改写中的无依据数字/技能能被标记或删除；新事实需确认；修改可撤销 |
| A07 | 当前版本可导出有效 PDF/DOCX；编辑后旧检查失效；失败可重试且无重复扣额 |
| A08 | 下载、打开外站后状态仍不变；明确确认后才 Applied，并保留提交版本 |
| A09 | 刷新/离开后任务仍可找回；重试不重复创建申请；一项失败不丢另一项产物 |
| A10 | 同公司同职位的两次申请互不覆盖；账户 A 无法读写账户 B 的资料或文件 |
| A11 | 资料和账户删除有范围确认；活跃任务取消/阻止写回；数据导出有鉴权与过期链接 |
| A12 | 额度耗尽不删除材料、不阻止已有产物下载；无隐藏收费或自动购买 |
| A13 | 375px 可导入、查看、更新状态；键盘可完成核心路径，焦点与错误提示清晰 |
| A14 | 追问只答当前职位与本人资料范围；每条回答可定位到原文行；原文未说明的内容回答「未说明」，不补写通用建议，也不触发任何写操作 |
| A15 | 结构化结果不可用时，界面降级为定性表述并给出重试入口；不出现伪造的条数、改动理由或 0 |

## 8. 云端产品新增的底线

此处只约束产品可交付性，不提前选择技术栈：

- 鉴权、租户隔离、最小权限文件访问；所有文件下载经过授权或短期签名。
- 模型输入只包含当前任务所需资料；不上传整份历史；遥测不记录简历正文和 JD 全文。
- URL 获取防 SSRF，重定向同样校验；拒绝内网、环回、云元数据地址及非 HTTP(S) 协议。
- 文档解析隔离，大小/类型/压缩包展开限制；禁止执行用户文档和自定义模板代码。
- 外部职位文本视为不可信数据，不能获取文件/凭据或指挥工具；不能仅靠提示词当安全边界。
- 任务有超时、有限重试、幂等键、费用上限；模型不可用时保留资料、编辑与已有下载。
- 必须有处理方和保存期限说明；训练使用政策在供应商合同确认后才能对外承诺。
- 建议删除承诺：立即撤销访问与新任务，在线数据 7 天内清除，备份 30 天内过期；这是待运营验证的目标，不是现有系统能力。

## 9. 验证计划与退出标准

第一阶段建议招募 10–15 位真实求职者做任务测试，再做 30–50 位邀请测试。均为建议样本，不是统计充分性保证。

| 假设 | 观察方法 | 预设决策线（待确认，非现有成绩） |
|---|---|---|
| 用户能独立走通 | 首次导入到下载，全程观察 | 至少 80% 无主持人帮助完成核心任务 |
| 有明显效率收益 | 与本人惯常方式做近似任务比较 | 中位耗时至少降低 30%，同时检查质量没有下降 |
| 有重复使用价值 | 首次导出后 7 天内处理第二个真实职位 | 目标至少 30%；同时访问低留存用户了解是否已结束求职 |
| 输出可信 | 经用户核对，记录错误事实与改写幅度 | 严重事实错误必须修复后再扩大测试，不能以平均分掩盖 |
| 成本可支撑商业化 | 按成功材料包计入失败/重试的完整成本 | 先测模型、渲染、存储与支持成本，再制定价格 |
| 有付费意愿 | 针对完成真实任务的用户访谈/明确购买意向 | 访谈不能替代实际成交；下一轮单独设计付费实验 |

关键事件：`profile_confirmed`、`job_imported`、`fit_viewed`、`draft_requested`、`draft_reviewed`、`export_succeeded`、`applied_confirmed`。按独立申请 ID 去重；生成成功不等于下载，下载不等于投递。

面试率和 offer 率作为较长期、用户自报指标，不能作为首版短期验收，也不能把变化归因于产品本身。
