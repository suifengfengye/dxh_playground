# 工作 3：页面架构与低保真设计方向

状态：待确认。此文件只确定信息架构、任务流程、风格方向和交互约束，不定义最终视觉 UI。

## 1. 设计意图

面向美国非技术求职者，提供熟悉的“列表 → 详情 → 文档编辑 → 下载”路径，而不是要求用户学习提示词、Agent、Token、编译器或目录结构。

主对象是一次申请 `Application`：承载职位、分析、材料版本和进展。所有阶段都围绕同一对象，避免在聊天记录里找结果。

核心原则：

1. 一屏一个主要决策：确认资料、判断职位、编辑材料或确认投递。
2. 先解释，再操作：展示“为什么适合/哪里不确定”，随后才开始生成。
3. 人对外部动作负责：下载不是投递，模型推断不是用户事实，草稿不是提交版本。
4. 渐进披露：可选经历、求职信、薪资偏好按需展开，不用长问卷挡住第一次价值。
5. 失败可恢复：输入不丢、产物不覆盖、后台任务可离开、重试成本透明。

## 2. 风格方向

建议方向：**安静、专业、内容优先的文档工作台**。

| 维度 | 本轮决定 | 本轮不决定 |
|---|---|---|
| 气质 | 克制、可信、实用，不做招聘娱乐化 | 品牌名称、Logo、插画 |
| 结构 | 稳定导航、清晰列表、分段表单、对照审阅 | 精确栅格/间距 Token |
| 密度 | 列表中等密度，资料录入和文档编辑偏疏朗 | 最终字号、字体家族 |
| 层级 | 标题、正文、辅助说明、主动作明确分层 | 颜色值、渐变、阴影、圆角 |
| 反馈 | 文本状态与阶段，少量必要提示 | 动效曲线、品牌状态色 |
| 草图表现 | 黑白灰矩形、文本、线框、注释 | 高保真组件、装饰图片、真实 UI 实现 |

不选择“全屏聊天”“游戏化打卡”“炫技 AI 动画”“大型数据仪表盘”。它们会分散逐份申请的主要任务。

### 技能检索记录

使用 `ui-ux-pro-max` 本地知识检索，不是在线设计生成器。

- `job search productivity workspace --design-system`：返回 Flat Design 与营销漏斗模式；扁平、少装饰可参考，但漏斗不适用于应用内工作台，返回的编辑式字体搭配也不适用，未保存为设计系统。
- 收窄 `minimal productivity dashboard --domain style`：命中 `minimalism-and-swiss-style`，与专业工具的功能性、结构清晰方向一致；仅采纳方向，不照搬配色/字距。
- `progress feedback long running tasks --domain ux`：命中 Feedback / Progress Indicators，用于展示真实阶段；不捏造完成百分比。
- `error summary validation --domain ux`：命中 Focusable Error Summary 与字段错误，用于资料和职位导入。
- 本轮不执行 `--persist`，避免将未批准的颜色、字体、Token 当作最终设计决策。

v2 录入链路改版新增检索（同样只用本地知识库）：

- `progressive disclosure onboarding --domain ux`：命中 Onboarding / User Freedom——提供 Skip 与 Back，不强制线性不可跳过的引导。
- `long form reduce fields multi step --domain ux`：命中 Progress Indicators、Required Indicators——多步流程要给进度，必填项要明确标记。
- `conversational assistant natural language input --domain ux`：命中 Input Labels、Submit Feedback——即使采用对话录入，凡出现字段仍必须有可见标签，提交要有 loading 与成功/失败反馈。
- 另使用 `job-stories` 与 `customer-journey-map` 两个技能产出可验收的需求与流失点分析，结果见 [录入链路需求](05-intake-requirements.md)。

```text
P01 Welcome / Sign in
  |
  +-- 新用户 -> P02 Build your profile（对话 + 事实清单，单页）
  |                                    |
  +-- 老用户 --------------------------+--> P03 Applications
                                              |
                          +-------------------+-----------------+
                          |                                     |
                    P04 Add job                         现有申请记录
                          |                                     |
                          +--------------> P05 Job details <----+
                                               |
                                        P06 Documents
                                               |
                                     P07 Review & export
                                               |
                                   外站手动投递 / D01 记录状态
                                               |
                                        P03 Applications

常驻辅助入口：
P08 My profile：与 P02 同构的「对话 + 清单」，用于更新长期事实；不混入每个职位的定制材料
```

导航只保留 Applications、My profile、Settings。Documents 属于申请内部，不设孤立材料库；无 Search、AI Chat、Analytics、Interview 导航。对话是 P02/P08 内的录入与追问机制，不是独立页面，也不做聊天式首页。

## 5. 页内结构和重要选择

本节各页面的共同原则：**AI 先给出结论与下一步，用户只做确认、修正与否决**。落到具体页面即：不让用户从空白字段开始，不让用户自己从状态里推断该做什么，AI 的每个判断都要能点到依据、能回退。

### P02 对话负责输入，清单负责事实

原 v1 把录入做成「导入 → 核对 → 偏好」三步表单，问题不在步骤数量，而在**顺序**：它让用户先做苦力，AI 才出场。v2 改为单页双视图。

- 主区是对话与事实卡片。AI 先抽取、先给结论，用户只做 `Looks right / Edit / Remove`，而不是从空白字段开始填写。
- 右栏是清单，分 `Required to start / Waiting on you / Optional / Asked later` 四组。用具体条目表达进度，**不用百分比**，避免把档案完成度变成焦虑来源。
- 点击任一条目就地展开为带可见标签的字段。用户手写文本与 AI 生成文本分开存储，AI 重写不得覆盖用户文本。
- 硬必需只有姓名、邮箱与一段真实经历；未满足其余项也能进入工作区。
- 工作授权、地点、薪资不在本页出现，等具体职位命中时就地提问一次。
- `Skip` 与 `Finish later` 常驻；未确认的提取结果不得用于生成材料。
- 窄屏右栏折叠为清单抽屉，显示待处理数量。

改版依据（job stories、旅程图与所用 UX 规则）见 [录入链路需求](05-intake-requirements.md)。

### P03 首屏先说「今天需要你做什么」

页面顶部是一条 Assistant 建议条，用自然语言说明哪份申请要处理、为什么。列表新增 `Assistant read` 列，用一句话给结论（几条要求有证据、有无待决定项、是否临近截止），取代让用户自己解读状态列。

默认显示全部申请，筛选提供 Saved、Drafting、Ready、Applied、Interview、Offer、Closed。每行给一个与状态匹配的下一步：

- Saved：View fit；分析失败则 Retry analysis。
- Drafting：Resume editing；后台仍在生成则 View progress。
- Ready：Download；不偷偷改为 Applied。
- Applied / Interview / Offer：Update status。
- Closed：View history。

建议条只基于用户已导入的职位与当前状态生成，不推荐用户没添加过的岗位，避免变成投递推荐机器人。首版使用列表而不是可拖拽看板：日期、版本和下一步更清楚，也避免拖拽误改状态。Closed 仍可筛选访问。

### P04 AI 先读，再给结论

导入后 AI 先把结果摆出来：公司、职位、地点、工作方式，以及「找到了几条要求」。公司名与职位名不再以空白必填字段出现，而是 AI 读出后可编辑的一行——用户做的是改错，不是填写。

原文里没有的字段（截止日期、薪资、签证赞助、团队规模）统一列为 `Not stated`，不猜测，也不留空让人填。受限来源引导粘贴正文，不自动更换职位或编造正文。

### P05 AI 的结论与下一步在前，证据对照在后

首屏是 Assistant 的结论卡片：用自然语言说明哪些要求被支持、哪一项没有证据，并给出明确建议——补一条事实，或接受这个缺口。之后才是"职位要求 ↔ 已确认经历"逐条对照。页内标签 Fit、Job posting、Activity；不重复开三个详情页面。

右栏提供 `Ask about this job`：只在当前职位范围内回答并引用原文行；答不出来就直说不知道，不用通用职业建议填空，也不是聊天入口。另有 `What I could not determine` 列出 AI 未确定的事项（签证赞助、公司文化等），并明确说明公司文化未做独立调研。

相同详情页允许只保存职位、直接记录外部投递、关闭记录，不强迫使用生成器。

### P06 AI 提议，用户保留否决权

电脑：编辑区占主要宽度，AI 动作与理由区占辅助宽度。选择段落才展开可用的改写动作（写短一点 / 对上这条要求 / 换成平实表达 / 我自己写），避免永远显示所有建议。

AI 只提议、不直接落稿：每次改写都由用户接受或回退，并写入 `Change log`。用户手写文本与 AI 文本分开存储，AI 重写不得覆盖用户文本。审阅阻塞时主动作保持不可用并说明原因，不给虚假的「已核实」。

Resume、Cover letter 是同页标签，尚未生成求职信时显示 Add cover letter，不展示空白编辑器。自动保存显示 Saving / Saved / Save failed；失败时不允许假装已保存。

### P07 下载和投递严格分离，失败必须可解释

依次显示当前版本、检查结果、文件选项、下载。用户可选择 Open original posting（新标签页），但打开外站不改变状态。独立的 Mark as applied 打开 D01，确认日期和提交版本。

检查失败时由 AI 说明具体原因（例如第 2 页文字不可提取，通常是文本框或图片）并给最小修复动作，同时提供有效的降级出口（DOCX / Copy text）。禁止只显示一个红色失败标记；失败文件永远不显示 Ready。

纯正文导入没有 URL 时，不出现无效的“打开原职位”动作；提示在原招聘网站自行投递。

### P09 数据边界要落到字段

除账户、用量、导出与删除外，新增 `What the assistant can see`：说明每次任务只发送当前职位与相关资料片段，不上传整份历史，并能展开到具体字段清单。只写「我们重视你的隐私」不算满足。

## 6. 对话框与局部状态

| ID | 类型 / 所在页面 | 内容与恢复路径 |
|---|---|---|
| D01 | 更新状态 / P03、P05、P07 | 当前/目标状态、实际日期、备注、提交版本或外部材料；确认后写事件 |

| S02 | 读取受限 / P04 | 保留 URL，切换 Paste description；说明不能读取，不称职位不存在 |
| S03 | 长任务 / P04–P07 | Queued / Reading / Drafting / Reviewing / Checking；可离开，失败单步重试 |
| S04 | 部分成功 / P06–P07 | Resume 已完成、信失败；分别保留与重试 |
| S05 | 资料或版本变化 / P05–P07 | 标明结果基于旧资料；主动重新分析/生成，不覆盖已编辑或提交版本 |
| S06 | 额度不足 / P05–P06 | 剩余额度、下次重置、已有文件仍可下载；无未经确认的付费入口 |
| S07 | 网络/会话过期 / 全局 | 不显示敏感缓存给已退出用户；重新登录后取回服务器已保存内容，提示未保存内容边界 |
| S08 | 疑似重复职位 / P04–P05 | 先按 URL 与岗位编号判定；仅公司或职位同名只作疑似，始终允许创建独立申请 |
| S09 | 来源或主资料已变化 / P05–P07 | 分析结果标记过期，由用户主动重跑；不覆盖已有草稿与已提交版本 |
| S10 | 保存失败 / P06 | 显示 Retry save 与文本复制出口；未成功保存前不显示 Saved，导出只对应最后一次成功保存的版本 |
| S11 | 追问答不出来 / P05 | 原文与资料均未说明时直接回答「未说明」，并给出查看原文的入口；不用通用职业建议填空 |
| S12 | 结构化结果不可用 / P03–P06 | 条数与改动归因降级为定性表述；不显示 0、不伪造条目，提供重试入口 |

## 7. 响应式与可访问性

- 电脑优先检查 1440 / 1024 宽度；平板 768；手机至少检查 375。尺寸为后续原型验证目标，本轮不宣称已完成真机测试。
- 手机用顶部菜单替代常驻侧栏；申请表格改纵向卡片，保留岗位、公司、状态、下一步。
- 适配依据上下堆叠；文档编辑按章节展开，证据在正文后展开，不要求并排操作。
- 手机仍能编辑和下载；可建议电脑更方便，但不能硬阻断核心动作。
- 表单提供可见标签、必需/可选区分；提交失败聚焦错误摘要，错误链接到字段。
- 所有动作支持键盘，弹窗进入时管理焦点、退出时返回触发按钮；无需靠拖拽、悬停或颜色理解状态。
- 长任务阶段由真实服务端状态驱动，阶段文本可被辅助技术读取；不连续抢焦点。
- 用 Sep 19, 2026 等明确日期展示；后台保存 ISO 日期；截止日期无时区信息时原样说明，不能擅自加倒计时。
