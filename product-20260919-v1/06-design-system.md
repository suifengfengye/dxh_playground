# 工作 4：设计系统

版本：v2 / 2026-09-20。性质：视觉方向与 Token 定稿，**已在 `prototype/` 交互稿中验证过一遍**。
输入来源：`ui-ux-pro-max` 本地知识库检索、`design-system` 技能的三层 Token 架构、以及 03/05 已确认的交互结论。
交付载体（用户已选）：静态高保真 HTML 稿。

> **v2 变更说明**：v1（墨色极简 + 青色只给 AI）评审后判定"过于朴素，看不出 AI 与工作感"，且识别色对白底对比度只有 3.7:1。v2 重新定调并替换整套色彩与品牌层，交互稿同步重做。§9 记录了本次推翻的 v1 决策。

## 1. 一句话方向

**冷静的信号台：冷调纸面工作台 + 靛蓝品牌 + AI 与品牌同源同色。**

### 1.1 定调关键词（AI + Job）

| 关键词                    | 含义                                   | 落到界面上                                                               |
| ------------------------- | -------------------------------------- | ------------------------------------------------------------------------ |
| **证据感 Evidence**       | 每个 AI 结论都能回溯到一条来源         | 事实卡带 `Extracted from resume.docx` 来源标签；AI 区块三重编码          |
| **推进感 Momentum**       | 求职是一条向前的流水线，不是一堆文档   | 登录页三步 AI 流水线；状态从 Saved → Drafting → Ready → Applied 一路可见 |
| **信号 Signal**           | AI 有一个专属颜色，一眼可辨            | 靛蓝语义层 + 渐变 sparkle 标记；AI 卡片固定左色条 + `Assistant` 标签     |
| **冷静的纸面 Calm paper** | 简历仍然是纸，长文要能读               | 冷调纸白画布、边框分层而非阴影、正文 Source Sans 3                       |
| **开源的工匠感 Craft**    | 精确、克制、可辨识，适合挂在 GitHub 上 | JetBrains Mono 只用于模型名与端点；无插画、无 emoji、无装饰动画          |

### 1.2 为什么品牌色就是 AI 色

v1 把品牌色与 AI 色强制分离（按钮墨黑、青色只给 AI）。v2 反过来：**这个产品本身就是 AI，品牌色与 AI 语义层同源**。用户想要的"AI 感"来自整屏都有一致的靛蓝信号。

代价与补偿：v1 担心的"AI 提议 / 我确认的 / 系统事实"三分，v2 用**色相**继续保证 —— 靛蓝（AI 提议）、绿（我确认的）、墨/中性（系统事实）三者互不重叠，且 AI 区块仍坚持三重编码（标签文字 + 3px 左色条 + 浅底），灰度或色盲下依旧可辨。

## 2. 知识库给了什么，我否决了什么

必须说明：检索返回的是一套通用"Productivity Tool"配置，其中三处与我们的产品冲突，不能照抄。

| 返回项                                                     | 处理           | 原因                                                                                                          |
| ---------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------- |
| 模式 `Product Demo + Features`（Hero > 视频 > 卖点 > CTA） | **否决**       | 那是营销落地页的漏斗结构。我们的对象是应用内工作台，不是获客页。与 v1 否决"营销漏斗"一致                      |
| 背景色 `#F0FDFA`（浅青底）                                 | **否决**       | 这是文档工具。用户要判断简历在纸上的效果，带色背景会干扰对"纸白"的感知；大面积浅青还会把界面推向健康/水疗语域 |
| 强调色 `#EA580C`（橙）作 CTA                               | **否决**       | 响亮橙色与"安静、专业"冲突，且与青同时出现会抢注意力。橙色改作**语义色**：只表示"需要注意"                    |
| 风格 `Flat Design` 中的 "bold colors / icon-heavy"         | **部分否决**   | 采纳"扁平、无渐变、少装饰"，不采纳高饱和与图标堆砌                                                            |
| 字体 `Plus Jakarta Sans` 为唯一字体                        | **降为备选**   | 圆润友好的气质偏消费级；文档工作台更需要长文可读性与中立感                                                    |
| 主色 `#0D9488` 直接当正文/链接色                           | **否决该用法** | 对白底对比度约 **3.7:1**，达不到正文 4.5:1 的 AA 标准。文字改用 `#0F766E`（约 5.0:1），原色只用于大图形与图标 |

**采纳的部分**：扁平淡雅的方向、无渐变、简单 hover、150–200ms 过渡、少而一致的图标；以及它的无障碍清单（对比度、可见焦点、reduced motion、禁用 emoji 当图标、375/768/1024/1440 断点）。另外它列出要避免的 `Complex onboarding`，与我们刚砍掉三步表单的方向一致，可作为旁证。

## 3. 色彩系统

三层结构：Primitive（原始值）→ Semantic（用途）→ Component（组件）。组件里不写十六进制。

### 3.1 Primitive

--neutral-100: #f1f3f6;
--neutral-200: #e4e7ec;
--neutral-300: #d0d5dd;
--neutral-400: #98a2b3;
--neutral-600: #475467;
--neutral-800: #1d2939;
--neutral-900: #101828;

/* 品牌 = AI 家族：靛蓝 */
--brand-50: #eef2ff;
--brand-100: #e0e7ff;
--brand-200: #c7d2fe;
--brand-300: #a5b4fc;
--brand-500: #6366f1;
--brand-600: #4f46e5;
--brand-700: #4338ca;
--brand-900: #312e81;
--signal-400: #22d3ee; /* 只做渐变搭档，不做大面积 */

### 3.2 Semantic

| Token                   | 值        | 用途                 | 对白底对比度 |
| ----------------------- | --------- | -------------------- | ------------ |
| `--color-canvas`        | `#F7F8FA` | 应用背景（冷调纸面） | —            |
| `--color-surface`       | `#FFFFFF` | 卡片、文档纸面       | —            |
| `--color-border`        | `#E4E7EC` | 常规分隔             | —            |
| `--color-border-strong` | `#D0D5DD` | 表格头、需强调边界   | —            |
| `--color-text`          | `#101828` | 正文与标题           | ≈16.9:1      |
| `--color-text-muted`    | `#475467` | 辅助说明、时间戳     | ≈8.0:1       |
| `--color-primary`       | `#4F46E5` | 主按钮底、链接、焦点 | —            |
| `--color-on-primary`    | `#FFFFFF` | 主按钮文字           | ≈6.9:1       |
| `--color-attention`     | `#B45309` | 需复核、临近截止     | ≈5.0:1       |
| `--color-success`       | `#047857` | 检查通过、已确认     | ≈5.4:1       |
| `--color-danger`        | `#DC2626` | 破坏性操作、检查失败 | ≈4.8:1       |
| `--color-focus-ring`    | `#4F46E5` | 键盘焦点环           | ≈6.9:1       |

对比度为按 WCAG 相对亮度公式手工计算，**实现阶段必须用工具复算**（真实字号/字重会改变结论）。

### 3.3 AI 语义层（本产品的特殊需求）

草图里反复出现"AI 提议 vs 用户确认"，这需要在 Token 层就固定，而不是每个页面各画各的。v2 起这一层与品牌层同源（见 §1.2）。

| Token          | 值        | 用途                                     |
| -------------- | --------- | ---------------------------------------- |
| `--ai-surface` | `#EEF2FF` | AI 结论卡、改动日志底色（小面积）        |
| `--ai-border`  | `#C7D2FE` | AI 卡片边框                              |
| `--ai-text`    | `#4338CA` | AI 相关文字                              |
| `--ai-mark`    | `#4F46E5` | 左侧色条、AI 头像、进度                  |
| `--ai-grad`    | 见下      | **唯一允许的渐变**，仅品牌标记与 AI 头像 |

```css
--ai-grad: linear-gradient(
  135deg,
  var(--brand-500) 0%,
  var(--brand-600) 45%,
  var(--signal-400) 100%
);
```

渐变的使用纪律：只允许出现在 `.orb`（品牌标记 / AI 头像，≤30px）与 `.bar i`（进度填充）上。**禁止**用它做卡片底、页面背景、大面积插画。

**强制规则**：AI 内容不能只靠颜色区分。每个 AI 区块必须同时满足三条 —— 固定标签文字（`Assistant`）、左侧 3px 色条、浅底。色盲用户与灰度打印下仍然可辨。

## 4. 字体系统

### 4.1 三套字体必须分开，不能混为一谈

| 用途                              | 字体              | 理由                                                                                   |
| --------------------------------- | ----------------- | -------------------------------------------------------------------------------------- |
| 产品 UI（标题、按钮、标签、表格） | **Lexend**        | 为阅读能力设计的字体，可读性与无障碍表现优于圆润型字体                                 |
| 长文阅读（职位原文、说明文字）    | **Source Sans 3** | 正文阅读舒适，字重齐全                                                                 |
| **简历 PDF 模板**                 | **本轮不选**      | 这是交付给雇主和 ATS 的文件，不是产品界面。必须单独按 ATS 可解析性选型，与 UI 字体解耦 |

第三行是最容易出错的地方：把界面字体塞进简历模板，可能让 PDF 在 ATS 解析或雇主观感上出问题。留到模板设计阶段单独决策。

### 4.2 字阶与排版

```css
--font-ui: "Lexend", system-ui, sans-serif;
--font-reading: "Source Sans 3", system-ui, sans-serif;

--text-caption: 12px; /* 时间戳、辅助说明 */
--text-sm: 13px; /* 表格、密集列表 */
--text-body: 15px; /* 默认正文 */
--text-lg: 18px; /* 区块标题 */
--text-h3: 20px;
--text-h2: 24px;
--text-h1: 30px;

--leading-tight: 1.25; /* 标题 */
--leading-body: 1.55; /* 正文 */
--measure: 68ch; /* 长文最大行宽 */
```

规则：日期与计数用 tabular figures（等宽数字），否则表格里的日期会跳动；长文不超过 `--measure`，避免宽屏上一行读到底。

## 5. 间距、圆角、层级、动效

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;
--space-12: 48px;

--radius-sm: 4px; /* 输入框、chip */
--radius-md: 6px; /* 按钮、卡片 */
--radius-lg: 10px; /* 对话框、面板 */

--motion-fast: 120ms;
--motion-base: 180ms;
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);
```

**层级策略：用边框分层，而不是阴影。** 只有对话框与下拉浮层允许一层轻阴影。原因是这个产品是高密度列表 + 文档预览，多层阴影会让界面发脏，也让"纸面"失去平面感。

动效：只用于状态切换与浮层进出；`prefers-reduced-motion` 下关闭非必要动效；禁止做数字滚动之类的装饰动画。

## 6. 状态色：把状态和颜色解耦

状态很多，如果每个状态一个颜色会变成彩虹，反而看不懂。规则如下。

| 状态组                                                                      | 表现                                           | 是否用色 |
| --------------------------------------------------------------------------- | ---------------------------------------------- | -------- |
| 业务状态（Saved / Drafting / Ready / Applied / Interview / Offer / Closed） | 中性 chip + 文字；仅 Ready 与 Offer 用 success | 少量     |
| 事实状态（Needs confirmation / Confirmed / Optional / Missing）             | attention / success / 中性 / 中性              | 是       |
| 检查结果（Pass / Fail / Not stated / Reviewed by you）                      | success / danger / 中性 / 墨色+对勾            | 是       |
| 结构化结果不可用（S12）                                                     | **中性**，不是红色                             | 否       |

`Not stated` 与"拿不到结构化结果"都必须显示为中性，**不能显示 0、不能用红色** —— 它们不是失败，是未知。这条直接对应 02 的 A15。

| 对话框（D01–D03）                       | `--radius-lg`，唯一使用阴影的组件；有遮罩；焦点管理                                                                                         |

图标：统一用 **Lucide**（与 shadcn/ui 生态一致），线性、1.5px 描边，尺寸 Token 化（16 / 20 / 24）。**不用 emoji 当图标。**

## 8. 无障碍底线

- 正文对比度 ≥ 4.5:1；图形与边框 ≥ 3:1；焦点环可见且不被遮挡。
- 任何状态都不能只靠颜色：必须"文字 + 图标 + 边框"三重编码。
- 键盘可完成全部核心路径：登录 → 录入 → 导入职位 → 看适配 → 编辑 → 导出 → 更新状态。
- 表单字段始终有可见标签（对话式录入也一样），错误在顶部汇总并链接到字段。
- `prefers-reduced-motion` 生效；长任务进度由真实状态驱动，不伪造百分比。
- 断点：375 / 768 / 1024 / 1440。

## 9. 已确认的决策

### 9.1 v1（2026-09-19），v2 已推翻其中第 1 条

1. ~~**主 CTA 用墨黑（`#1C1917`），青色只留给 AI 语义层。**~~ **已推翻**，见 9.2-1。
2. **界面字体采用 Lexend + Source Sans 3。** 可读性优先于圆润友好；不采用 Plus Jakarta Sans。**v2 保留**，另加 JetBrains Mono 专用于模型名与端点这类技术字符串。
3. **首版只交付 light mode。** dark 仅保留语义层 Token 位置，不承诺可交付；简历 PDF 模板字体仍留待模板阶段单独决策。**v2 保留**。

### 9.2 v2（2026-09-20）定稿

1. **主 CTA 用靛蓝 `#4F46E5`，品牌色与 AI 语义层同源。** 判定 v1 的"墨色极简"过于朴素、看不出 AI 与工作感；同时 v1 的青 `#0D9488` 对白底只有 3.7:1，达不到正文 AA。三分（AI 提议 / 我确认的 / 系统事实）改由**色相**保证：靛蓝 / 绿 / 墨中性。
2. **画布从暖石色改为冷调纸面 `#F7F8FA`。** 暖石色偏"文档扫描件"，冷调更像软件，也让靛蓝能跳出来。
3. **`Build your profile` 从独占整页改成可中断的弹窗引导。** 工作台始终在背后可见；关闭后工作台保留 `Continue setup` 入口与百分比进度。引导状态是"两个必填项（联系方式 + 一段经历）"驱动，不是自由步进。
4. **允许一处渐变 `--ai-grad`（靛蓝 → 青）**，仅限品牌标记（`.orb`）与进度填充（`.bar i`），≤30px 面积。其余一律无渐变。
5. **左下角常驻"模型厂商配置"入口。** 这是开源版本的地基：不带 key 就没有 AI。未连接时工作台显示 `No model connected` 横幅，而不是让 AI 按钮静默失败。
6. **My profile 必须有可见的 AI 会话**（头像、消息流、建议 chip、composer），事实卡显示 `Extracted from …` 来源标签。这是"证据感"关键词的落点。
