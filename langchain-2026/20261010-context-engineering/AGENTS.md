## 1. 这个助手在做什么

用户用自然语言问「通勤穿的显瘦连衣裙，300 以内」「37 码帆布鞋还有货吗」，
助手在**毫秒级**内理解需求 → 检索商品 → 交叉核对实时库存价格 → 给出穿搭建议与替代方案。

上线 14 个月，它是商城的**主要导购入口**之一，不是 demo。
**所有回答必须以数据为准，宁可说「不清楚」，绝不编造商品、价格、库存、尺码。**

## 3. 生产架构（相对早期版本的演进）

```
用户输入
  ├─ 意图路由（闲聊 / 找货 / 比价 / 售后 / 尺码咨询 / 搭配）  ← 小模型，~8ms
  ├─ 多路召回
  │    ├─ 商品向量检索（语义）
  │    ├─ 商品倒排检索（类目/属性/尺码 硬过滤）
  │    ├─ 知识库检索（尺码表/政策/养护）
  │    └─ 用户历史（画像 + 近期会话）
  ├─ 重排（cross-encoder + 转化率/点击率特征）   ← 产出 top-K
  ├─ 实时事实核验
  │    └─ 价格 / 库存 / 促销 → 交易系统 API（**唯一可信源**）
  ├─ 生成（DeepSeek V4 系）
  ├─ 安全与合规后置校验（幻觉检测 / 敏感词 / 承诺校验）
  └─ 输出 + 埋点
```

**关键演进（相对 v1）**：早期 `Chroma` 本地库 → 自建向量服务（分片 + 多租户 + 增量 upsert）；
早期 `InMemorySaver` → Redis（会话）+ Postgres（长期画像）；早期单模型 → 路由小模型 + 生成大模型。

## 4. 数据资产与 Schema（最重要的部分）

### 4.1 商品事实（商品域，实时同步）
```jsonc
{
  "sku_id": "SKU-8842-017",       // 稳定主键，跨版本不变
  "spu_id": "...",
  "title": "...",
  "category_path": ["女装","连衣裙","针织"],
  "attributes": {"面料":"纯棉","版型":"直筒","袖长":"无袖"},
  "size_range": ["S","M","L","XL"],
  "price": {"current": 299, "list": 359, "currency": "CNY"},
  "stock": {"M": 12, "L": 0},
  "seller_id": "...",
  "status": "on_sale",            // on_sale / off_shelf / sold_out
  "updated_at": "2026-09-30T08:11:02+08:00"
}
```
> **价格与库存不写进向量库**（会过期）。向量里只放**稳定的语义描述**，价格/库存**每轮实时查**。

### 4.2 向量化文本（离线生产）
每个 SKU 生成多条向量：`标题` / `卖点+属性` / `买家评价摘要` / `搭配描述`。
字段带 `source_type`，检索时可按权重加权。

### 4.3 会话与反馈
- 表 `chat_session` / `chat_turn`：完整对话、检索命中、模型版本、延迟、成本。
- 表 `user_feedback`：点踩、退货归因、转化回传（下单与否）。
- 表 `badcase`：人工/自动筛出的失败样本，含期望行为。

### 4.4 用户长期画像（个性化依据，受隐私约束）
偏好类目、惯用尺码、价格带、风格标签。**仅存聚合标签，不存原始敏感对话**（见第 11 节）。

## 7. 检索与 Embedding 演进

- Embedding 模型：智谱 `embedding-3`（2048 维，OpenAI 兼容）→ 当前主用 **多模型混合**（中文语义 + 图文）。
- **向量模型变更 = 全量重嵌入事件**：必须走「双写 → 影子评测 → 灰度切流 → 回滚预案」流程，**禁止直接热替换**（原因见第 9 节事故 A）。
- 召回：多路 → 融合（RRF）→ 重排（cross-encoder + CTR/CVR 特征）。
- 缓存：查询级语义缓存（命中率 ~34%）+ embedding 缓存，用于控成本与降 P95。
- 分区：按类目/商家分区，避免长尾淹没。

## 8. 评测与质量门禁

**离线（每次发版必跑，不过不许上）**

| 指标 | 门槛 | 当前 |
|---|---|---|
| 检索 Recall@10 | ≥ 0.92 | 0.94 |
| 事实准确率（价格/库存/尺码） | ≥ 0.995 | 0.997 |
| 幻觉率（编造商品/参数） | ≤ 0.2% | 0.11% |
| 黄金回归通过率 | = 100% | 100% |

**线上（持续观测）**

| 指标 | 当前 |
|---|---|
| 导购转化率 | 8.7% |
| 点踩率 | 0.9% |
| P95 端到端延迟 | 1.4s |
| 单会话平均成本 | ¥0.021 |

**流程**：离线门禁 → 影子流量（1%）→ 灰度（5%→20%→50%）→ 全量；任一阶段指标劣化超阈值即**自动回滚**。

## 9. 历史事故与教训（从数据里踩出来的，别重犯）

**事故 A · 向量模型热替换导致召回崩塌（上线第 5 月）**
直接换了新 embedding，未重嵌入历史库，新旧向量空间不兼容 → 召回率从 0.9 掉到 0.3，转化率腰斩。
**规则**：模型变更必须全量重嵌入 + 双写灰度，见第 7 节。

**事故 B · 早期把商品 bulk 塞进 prompt（上线第 2 月）**
为图省事把热销榜塞进 system prompt，某次促销商品数暴涨 → 上下文超限 + 成本飙升 20 倍。
**规则**：商品/知识永远走检索，见第 2 节第一原则。

**事故 C · 编造尺码/库存（多次）**
模型在检索为空时「脑补」了不存在的 M 码库存，导致用户下单失败投诉。
**规则**：涉价格/库存的回答，**先调实时核验工具**；查不到必须说「暂时没有」。

**事故 D · 缓存了实时价格（上线第 9 月）**
被缓存的旧价格在活动中展示，触发价保纠纷。
**规则**：价格/库存/促销**不进任何缓存**。

**事故 E · 用户历史被过度使用**
用早期未脱敏的原始对话做画像，触碰隐私合规。
**规则**：画像只用聚合标签，见第 11 节。

## 10. 成本与性能预算

- 单会话成本上限 **¥0.03**，当前 ¥0.021；超预算视为 P2 缺陷。
- P95 延迟上限 **2s**，当前 1.4s。
- 成本手段：语义缓存、embedding 缓存、路由小模型分流、检索窗口动态 top-K（按意图）。

## 11. 合规红线 [RUNTIME] —— 最高优先级，任何情况不得突破

1. **不编造**商品、价格、库存、尺码、政策；不确定就说「我帮您确认 / 暂不清楚」。
2. **价格库存以交易系统实时结果为准**，不得引用检索片段里的历史值。
3. **隐私**：不输出、不复述用户敏感信息；画像仅用聚合标签。
4. **不承诺**无法保证的事（到货时间、绝对效果、医疗/功效宣称）。
5. **不诱导**过度消费；未成年相关请求按公司策略处理。
6. 涉及退换/售后承诺，一律引用**知识库现行政策原文**。

## 12. 变更流程与 SLO

- 改 **Prompt / 检索参数 / 工具** → 必跑黄金回归 + 影子评估，附前后指标。
- 改 **数据 Schema** → 需兼容旧数据，迁移脚本 + 回滚。
- 改 **Embedding / 向量维度** → 走第 7 节全量重嵌入流程。
- **SLO**：可用性 99.9%，P95 < 2s；异常自动降级为「保守回答 + 人工兜底」。

## 13. 明确不做（Out of Scope）

- 不直接下单 / 支付 / 改价；不处理真实交易凭证。
- 不做医疗、功效、尺寸以外的身体评价类建议。
- 不接入未经合规评审的第三方数据。
